# Скрипты базы данных 

## Листинги для диплома

Готовый документ с нумерованными листингами (код + SQL) для вставки в пояснительную записку:

**`database/LISTING.md`**

## Где лежат файлы

| Файл | Назначение |
|------|------------|
| `schema.sql` | DDL: создание таблиц `users` и `user_profiles` |
| `queries.sql` | Примеры SELECT / UPDATE / DELETE для отчёта |
| `seed_example.sql` | Пример тестовых данных |
| `LISTING.md` | Листинги 1–7 для приложения к диплому |

## Где создаётся сама БД

После запуска сервера (`npm start`) файл базы появляется здесь:

```
data/app.db
```

Дополнительно SQLite может создать служебные файлы:

- `data/app.db-wal`
- `data/app.db-shm`

## Где схема в коде приложения

Схема автоматически применяется при старте сервера в файле:

```
server/db.js  →  функция initSchema()
```

Доступ к данным:

```
server/store.js
```

## Как выполнить скрипты вручную

Из папки проекта `kids`:

```bash
sqlite3 data/app.db < database/schema.sql
sqlite3 data/app.db < database/seed_example.sql
```

Просмотр таблиц:

```bash
sqlite3 data/app.db ".tables"
sqlite3 data/app.db "SELECT login, created_at FROM users;"
```

## Описание для пояснительной записки

**users** — учётные записи репетиторов (логин + хеш пароля).

**user_profiles** — данные приложения одного пользователя: критерии оценки, методики обучения, таблица подходящести, матрицы МАИ и список учеников с уроками. Вложенные структуры сериализованы в JSON, что упрощает синхронизацию с клиентским SPA без сложной нормализации на этапе прототипа.

Связь: один пользователь → один профиль (`1:1`, внешний ключ с `ON DELETE CASCADE`).
